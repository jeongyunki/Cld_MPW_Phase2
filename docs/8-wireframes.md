# MPW Plus 2차 개발 와이어프레임 (Wireframes)

> 작성 단계: 와이어프레임 (8/8, UI 설계 단계) — `docs/1-domain-definition.md` ~ `docs/7-execution-plan.md`에서 이미 확정된 기능 범위(PRD 3절 FR-DL/FR-MG/FR-IM/FR-MS), 화면 전환 순서(`docs/3-user-scenario.md`), 프론트엔드 Task 경계(`docs/7-execution-plan.md` FE-1~FE-7), 라우트/컴포넌트 네이밍(`docs/4-project-structure-principles.md` 6.1절)을 그대로 시각화한다. 실행계획 다음, 이 문서 체계의 마지막 단계다.
>
> 이 문서는 화면을 새로 기획하지 않는다. `src/routes/+layout.svelte`, `src/routes/mapgen/+page.svelte`, `src/routes/imgagong/+page.svelte`, `src/routes/master/+page.svelte`, `src/routes/+page.svelte`를 직접 읽고 확인한 **현재 실제 구현 구조**를 기준으로, "지금 이미 이렇게 동작한다" 위에 "이번에 새로 추가되는 요소"만 얹어서 표현한다.

## 0. 범례 (ASCII 와이어프레임 표기법)

저해상도(low-fidelity) 와이어프레임이다. 픽셀 단위 배치, 색상, 폰트 크기는 다루지 않는다(색상/CSS 변수 컨벤션은 `docs/4-project-structure-principles.md` 소관이 아니라 `+layout.svelte`의 `<style>` 소관이며, 이 문서 범위 밖이다).

| 표기 | 의미 |
|---|---|
| `┌─┐ └─┘ │ ─` | 화면/팝업/패널의 경계 박스 |
| `[ 버튼명 ]` | 클릭 가능한 버튼 |
| `[______]` | 텍스트/숫자 key-in 입력 필드 |
| `[v 선택 ]` | dropdown(select) 입력 필드 |
| `[ ]` / `[x]` | 체크박스 (미선택 / 선택됨) |
| `( 문구 )` | 화면에 표시되는 안내/설명 문구, 사용자 입력값 예시 |
| `⚠` | 에러/경고 메시지 |
| `✓` | 성공/완료 토스트 메시지 |
| `- - -` | 표/목록의 구분선 또는 생략된 반복 행 |
| `(1) (2) ...` | 와이어프레임 안의 번호 — 아래 "요소 설명" 목록과 대응 |

각 와이어프레임 하단에는 번호별 요소 설명과 근거(FR 번호 / 사용자 시나리오 단계 / Task 번호)를 표로 정리한다.

## 3. 거의 변경 없는 화면 (한두 줄만 언급)

### 3.1 Master Page (`/master`)

화면 UI는 `src/routes/master/+page.svelte` 그대로 유지된다(필드별 섹션 + chip 목록 + "새 항목 입력 후 Enter" 추가 폼). 내부 구현만 `masterStore.svelte.js`에서 백엔드 fetch로 교체된다(FE-3). **관리자 전용 화면**이라, 관리자가 아닌 사용자에게는 사이드바 "Master Page" 메뉴와 Welcome 카드가 보이지 않고 `/master`로 직접 들어와도 Welcome으로 이동한다(PRD 3.4절, 사용자시나리오 4절 예외 3-3 옵션 A, #37).

모든 화면의 브라우저 탭 제목은 사이드바 메뉴 이름과 같다("Welcome", "Deliverables", "MapGen Web", "임가공 Plan", "Master Page", 로그인 화면은 "로그인", #38).

### 3.2 Welcome (`/`)

`src/routes/+page.svelte`의 카드 목록은 변경되지 않는다. 다만 Deliverables Page가 신규 라우트로 추가되므로, 다른 카드들과 동일한 패턴으로 카드 한 개가 추가될 수 있다(문서상 요구된 범위는 아니며, 이 문서는 기능 변경을 다루지 않는다).
