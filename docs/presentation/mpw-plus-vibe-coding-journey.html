2막 · 판단을 맡기는 법

모르는 것은 "필요한지 판단해 달라"고 물었다

동영상에서는 아래 예시 프롬프트를 진행하라고 하네. 혹시 지금 내 과제에도 이 예시처럼 DDL 생성 과정이 필요한지 판단해주고 적절하다면 아래 예시대로 작업을 해줘. 만약 내 과제는 예시를 따를 필요가 없다면 알려줘. backend에 대해 잘 몰라서 내가 판단을 할 수가 없네.

필요하다는 판단과 이유 → database/schema.sql 생성. 이후 이 DDL은 Knex migration으로 옮겨졌고, "실제 스키마는 migration이 기준"이라는 규칙이 문서에 남음.

강좌 예시를 그대로 붙여 넣지 않고 "내 과제에도 맞는지"를 먼저 묻는 습관이 잘못된 산출물을 줄였습니다. 같은 방식으로 camelCase 필드명, 테스트 계정을 GitHub에 올릴지, MCP 설정을 저장소에 둘지도 Claude의 추천을 듣고 정했습니다.
