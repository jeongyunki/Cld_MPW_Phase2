# MPW Plus 도메인 정의서 (Domain Definition)

> 작성 단계: 도메인정의서 (1/6) — 다음 단계는 PRD → 페르소나 정의 → ERD 설계 → 실행계획 → UI 설계 순으로 진행한다.
> 이 문서는 핵심 개념과 범위를 정의하는 것이 목적이며, 기능 상세 명세(PRD)나 화면 설계는 다루지 않는다.

## 1. 배경 및 목적

**MPW Plus**는 사내에 공식 배포되어 있는, 반도체 MPW(Multi Project Wafer) 관련 업무를 효율화하기 위한 웹 시스템의 공식 명칭이다. Svelte 기반이며, 왼쪽 사이드바의 메뉴 목록에서 항목을 고르면 오른쪽에 해당 메뉴의 상세 화면이 표시되는 구조를 가진다.

- **1차 개발 (2026년 7월 완료, 타 개발자 담당)**: 사내에 실제 운영 중인 MPW Plus 시스템 본체. Deliverables 등록, Fab Out 공지 메일 발송, Assembly Workflow, 사용자/권한 관리를 담당한다.
- **2차 개발 (현재 진행, 이 저장소가 담당)**: MPW Plus에 신규 메뉴를 추가하는 추가 개발 건. **저장소 `Cld_MPW_Phase2`(폴더명 자체가 "2차 신규 기능 개발"을 의미)가 2차 개발의 대상**이며, 1차 시스템과는 별도 코드베이스에서 개발된다. 2차 개발이 완료되면 이 저장소의 코드를 1차 개발자에게 전달하여 MPW Plus 본체에 병합하는 방식으로 통합될 예정이다.

2차 개발은 1차 시스템과 동일한 Svelte 기술 스택을 사용해 메뉴를 계속 늘려가는 방식으로 진행하며, 이번 문서 작성 시점에는 향후에도 기능이 계속 추가될 예정임을 전제로 한다.

## 2. 문제 정의

- PC에 설치하는 GUI 프로그램(MPW SF Generator)이 사용자의 PC 환경에 따라 오동작하는 경우가 잦다.
- 임가공 처리를 위해 매월 이메일, 결재시스템, 재무시스템 등 여러 사내 시스템을 개별적으로 오가며 사용해야 한다.
- 개인별로 엑셀로 업무를 정리하다 보니 정보가 공유되지 않고 개인화되어 있다.

2차 개발의 성공 기준은 정량 지표까지는 아니지만, 정성적으로 다음 두 가지가 달성되면 위 문제가 해소된 것으로 본다: (1) PC 환경에 관계없이 MapGen Web이 동일하게 동작, (2) 개인별 엑셀 대신 공유되는 화면에서 업무 현황을 관리. 다만 두 번째 문제(여러 사내 시스템을 오가는 것) 중 결재·재무 시스템 연동 자체는 2차 스코프에서 제외되며, 이메일로 개별 처리하던 부분만 임가공 Plan 한 화면으로 통합한다(6절 참조). (2)를 위해 2차 개발에는 데이터를 영속적으로 저장하고 여러 사용자가 공유할 수 있는 백엔드(서버+데이터베이스)를 새로 구축하기로 확정했다 — 구체적인 기술 스택과 설계는 이후 ERD·실행계획 단계에서 정한다.

## 3. 용어 정의 (Glossary)

| 용어 | 정의 |
|---|---|
| MPW | Multi Project Wafer. 여러 프로젝트의 칩을 한 웨이퍼에 모아 생산하는 방식으로, 각 공정별로 정해진 회차(차수)에 생산된다. |
| Fab Out | 공장(Fab)에서 MPW 칩 생산이 완료되면 관련자에게 발송되는 공지. |
| Deliverables | MPW에 탑재된 module list와 Sawing Floorplan 정보. |
| Module | MPW를 구성하는 개별 IP. |
| Chip | MPW 웨이퍼 위에 배치되는 물리적 칩 단위로, 여러 module과 sawing line 정보를 포함한다. |
| Sawing Line | 웨이퍼를 칩 단위로 절단(sawing)하는 기준선. |
| MPW SF Generator | Module/Sawing Floorplan 도면을 생성하는 PC 설치형 GUI 프로그램 (1차 산출물). 사용자의 PC 환경에 따라 오동작이 잦아, 이를 대체하기 위한 웹 버전(MapGen Web)이 2차 개발 대상이다. |
| Assembly Decision | Fab Out 공지를 받은 담당자가 module을 package 형태로 조립할지 여부를 결정하는 단계. |
| Assembly Workflow | 조립 진행 6단계: EDS평가 → TR SCRAP → 조립의뢰 → 조립출하 → 조립투입 → 조립완료. |
| 임가공 | 외주 조립·가공을 의뢰하는 업무 전반. 현재 이메일 등으로 개별 처리하고 있어, 이를 하나의 화면으로 통합하는 것이 2차 개발 목표 중 하나다(결재·재무 시스템 연동 자체는 2차 스코프에서 제외, 2·6절 참조). |
| 조립처 | 임가공(조립)을 위탁하는 외주 업체. |
| 구분 | 임가공 Plan 행을 분류하는 카테고리 값. Master Page에서 옵션을 관리한다. (세부 분류 기준은 정의 필요) |
| Deliverables Page | 2차 개발에서 새로 만드는 화면. 이 저장소는 1차 시스템과 별도 코드베이스이며 백엔드/인증이 없는 프로토타입이라, 코드가 병합되기 전까지는 1차 시스템의 실제 Deliverables 데이터에 접근할 구조적 경로가 없다. 그 대신 엑셀 파일을 직접 업로드해 MPW 차수+공정명 단위로 등록하는 별도 프로토타입으로 구현한다. |

## 4. 시스템 범위

| 구분 | 1차 (MPW Plus 본체, 기존 운영 시스템) | 2차 (이 저장소의 개발 대상) |
|---|---|---|
| 위치 | 사내에 별도로 이미 운영 중, 타 개발자 담당 코드베이스 (이 저장소 밖) | `Cld_MPW_Phase2` 저장소 (폴더명 = "2차 신규 기능 개발") |
| 개발 상태 | 2026년 7월 완료, 운영 중 | 프로토타입 진행 중 |
| 담당 기능 | Deliverables 등록, Fab Out 공지 메일 발송(Assembly Workflow 포함), MPW SF Generator(PC 설치형) 배포, 사용자 등록/권한 부여 | MapGen Web(SF Generator의 웹 전환), 임가공 Plan(사내 조립 가공 업무를 하나의 페이지로 통합), Deliverables Page(2차 프로토타입 전용 신규 구현), 백엔드(서버+데이터베이스) 신규 구축 |
| 인증/권한 | 사용자 등록 및 권한 부여 기능 보유 | 현재 미구현. 자체 구현(Passport.js)을 1단계 목표로 먼저 완성하고, 이후 1차 개발자 협의 후 1차 체계로 전환 가능한 구조로 설계(8절, PRD 5절 참조) |
| 이 문서에서의 취급 | 배경 설명 목적으로만 서술, 상세 설계 대상 아님 | 본 도메인정의서 이후 단계(PRD 등)의 실제 설계 대상 |

이 저장소는 1차 시스템의 코드를 포함하지 않는다. 2차 개발이 완료되면 코드를 1차 개발자에게 전달하여 MPW Plus 본체(1차 시스템)에 병합하는 방식으로 통합될 예정이다(별도 배포 후 iframe 연결이 아니라 코드베이스 병합).

## 5. 핵심 워크플로우

전체 MPW Plus 워크플로우는 다음과 같다. 괄호로 각 단계가 1차(기완료)와 2차(신규) 중 어디에 해당하는지 표시한다.

1. **MPW Deliverables 등록** — Fab Out 담당자가 module list, Sawing Floorplan 정보를 등록 *(1차, 기완료)*
2. **Fab Out 공지** — 생산되는 MPW의 상세정보를 입력·저장하면 사내 이메일 시스템과 연계되어 등록된 담당자에게 자동 메일 발송 *(1차, 기완료)*
3. **Assembly Decision** — 메일을 받은 담당자가 module을 package로 조립할지 결정 *(1차, 기완료)*
4. **Assembly Workflow** — EDS평가 → TR SCRAP → 조립의뢰 → 조립출하 → 조립투입 → 조립완료 *(1차, 기완료, Fab Out 화면 내 포함)*

2차 개발은 이 워크플로우 자체를 새로 만드는 것이 아니라, 그 앞뒤에서 쓰이는 보조 도구(SF Generator의 웹 전환, 임가공 처리 과정의 통합)를 추가하는 성격이다. 다만 1단계 Deliverables 등록은 이 저장소가 1차 시스템의 실제 데이터에 접근할 수 없어(3절 Deliverables Page 정의 참조), 2차 프로토타입 전용의 별도 Deliverables Page를 새로 구현한다.

- Deliverables Page(2차 신규)에 등록된 "차수+공정명" 목록에서 원하는 항목을 팝업으로 선택해 엑셀 파일을 읽어와 도면을 그리는 것이 MapGen Web의 입력 방식으로 추가된다 *(2차, 신규 — 자세한 내용은 6절 참조)*.
- 임가공(외주 조립·가공 의뢰) 업무는 위 Assembly Workflow와 **독립적인 별도 기능**이다. Assembly Workflow가 특정 MPW 차수의 module을 조립할지 결정하고 그 진행 상태를 관리하는 워크플로우인 반면, 임가공 Plan은 매월 발생하는 외주 가공 업무 일정·현황을 관리하는 별개의 관리 페이지이며 Assembly Workflow의 진행 상태를 참조하거나 연동하지 않는다. 임가공 Plan의 목표는 기존에 이메일 등으로 개인별 엑셀 정리하던 방식을 하나의 화면으로 통합해 공유되도록 하는 것이다. *(2차, 신규)*

## 6. 2차 개발 핵심 기능 요약

기능 상세(화면 항목, 입출력 규격 등)는 다음 단계인 PRD에서 다룬다. 여기서는 "무엇을, 왜" 수준만 정리한다.

- **Deliverables Page (신규)**: 1차 시스템에는 이미 Deliverables 등록 기능이 있지만, 이 저장소는 그 데이터에 접근할 수 없다(3절 참조). 이를 위해 2차 개발 범위에 별도의 Deliverables Page를 새로 만든다.
  - "Create" 버튼을 누르면 팝업이 뜨고, "MPW 차수"와 "공정명"을 key-in한 뒤 엑셀 파일을 업로드해 저장한다.
  - 저장한 항목은 MPW 차수+공정명이 표시된 표에 행으로 추가되며, Create할 때마다 표 아래로 계속 쌓인다.
  - 이 페이지가 생기면 MapGen Web이 파일 선택 방식을 바로 구현할 수 있게 된다.
- **MapGen Web**: PC 설치형 MPW SF Generator를 웹으로 전환해, 개인 PC 환경(설치 상태, 버전 등)에 따른 오동작 문제를 없앤다. 입력 방식은 두 가지를 함께 제공한다.
  - 기존 방식(유지): 엑셀 셀 범위를 복사해 `<textarea>`에 붙여넣기.
  - 신규 방식: "Excel 파일 선택" 버튼을 누르면 Deliverables Page에 등록된 "차수+공정명" 목록이 표 형태의 팝업으로 뜨고, 원하는 항목(차수+공정명)을 선택하면 그 항목에 등록된 엑셀 파일을 읽어와 자동으로 그린다.
- **임가공 Plan**: 이메일 등으로 개인별 엑셀 정리하며 처리하던 임가공 업무를 MPW Plus 안의 하나의 페이지로 통합해 공유되도록 한다. 결재·재무 시스템 연동 기능("품의상신", "예산정보")은 2차 스코프에서 제외한다(관련 버튼은 화면에서 삭제 예정).
- **백엔드 (신규)**: 현재 브라우저 메모리에만 있는 데이터(임가공 Plan, Deliverables Page 등)를 서버와 데이터베이스에 영속적으로 저장해, 새로고침해도 유지되고 여러 사용자가 같은 데이터를 공유하도록 한다. 구체적인 기술 스택·API 설계는 다음 단계(ERD·실행계획)에서 정한다.
- 이 외에도 향후 계속 기능이 추가될 예정이다 (현재 시점에 구체적으로 확정된 항목은 없음).

## 7. 현재 저장소 구현 상태와의 관계

이 저장소에는 현재 4개 라우트가 구현되어 있으며, 모두 **백엔드 없는 클라이언트 전용 프로토타입**이다 (상태는 브라우저 메모리에만 존재하고 새로고침 시 초기화됨). 인증/로그인 기능도 없다. 2차 개발 범위에 백엔드 구축이 포함되기로 확정됐지만(2·6절 참조), 이 문서 작성 시점 기준으로는 아직 착수 전이며 아래 설명은 현재 코드 상태를 그대로 기술한 것이다.

- **Welcome (`/`)**: 홈 화면.
- **MapGen Web (`/mapgen`)**: 엑셀 셀 범위를 복사해 `<textarea>`에 붙여넣으면 자동 파싱하여, 칩 이미지 위에 module 사각형/sawing line/치수 화살표를 canvas로 그린다(입력 방식 확장 계획은 6절 참조).
- **임가공 Plan (`/imgagong`)**: 계획 행을 관리하는 테이블(Create 팝업, 조회 기간 필터, 체크박스 선택 삭제). "품의상신"/"예산정보" 버튼은 현재 코드에 비활성 placeholder로 남아있으나, 결재/재무 시스템 연동은 2차 스코프에서 제외되어 삭제될 예정이다.
- **Master Page (`/master`)**: 임가공 Plan에서 쓰는 dropdown 옵션(Status/구분/조립처/Chip size/PKG Type)을 추가·삭제하는 화면. 1차 시스템의 "사용자 등록/권한 부여"와는 이름만 유사할 뿐 별개 기능이다.
- **Deliverables Page**: 아직 이 저장소에 구현되지 않은 신규 기능이다(6절 참조).

즉, 현재 3개 실동작 페이지(MapGen Web, 임가공 Plan, Master Page)는 2차 phase의 목표 기능과 이름은 같지만, 아직 1차 시스템과 연동되지 않은 독립 프로토타입 단계다. Deliverables Page는 아직 착수 전이다.

## 8. 확인/결정이 필요한 미해결 사항

다음 단계(PRD/ERD)에서 반드시 다뤄야 할 항목을 놓치지 않기 위한 목록이다. (✅ 표시는 이번 개정에서 결정되어 해소된 항목)

- 구분 값 등 임가공 Plan에 이미 등장하지만 정확한 업무적 정의가 필요한 용어
